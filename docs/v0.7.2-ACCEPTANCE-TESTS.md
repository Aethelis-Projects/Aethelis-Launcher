# v0.7.2 — hardware acceptance checklist (pre-tag)

Headless CI (Go e2e on fixture servers, jsdom UI walk) proves protocols and wiring. These items can only be closed on physical machines — record PASS/FAIL per item; the tag goes on only after all are green.

## Windows, with a real Discord client
1. Toggle Discord presence ON in instance settings (Performance tab) → within ~5 s the Discord profile shows the "playing Minecraft" card; OFF → card disappears inside the 5 s acceptance window.
2. Discord **closed**: toggle on → status line must explain the failure (unreachable / pipe unavailable), launcher keeps working, no error dialogs; reopen Discord → presence auto-resyncs without touching the toggle.
3. Busy-pipe sanity (optional): open several Discord windows — the launcher must not hang (the dial runs under a 750 ms context; CI pins the contract, here confirm the UX is silent-degrade, not spinner).

## Real Modrinth .mrpack
4. Modpacks page → pick any pack with a `.mrpack` file → import: instance appears, plan/progress UI honest, launcher resolves the file **from its own API call** (devtools: the `ImportMrPackFromURL` payload carries only `project_slug` + `version_id` — no url, no hashes).
5. Launch the imported instance once (vanilla+mods resolve through the normal pipeline).
6. Mid-download network kill (pull LAN / firewall the CDN after ~50 %): status shows failed with transport error; retry works; `%TEMP%` contains **no** `nord-mrpack-url-*` leftovers (check Explorer/search).
