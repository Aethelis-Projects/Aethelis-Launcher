# v0.7.2 — hardware acceptance checklist (pre-tag)

Headless CI (Go e2e on fixture servers, jsdom UI walk) proves protocols and wiring. These items can only be closed on physical machines — record PASS/FAIL per item; the tag goes on only after all are green.

## Windows, with a real Discord client
1. Toggle Discord presence ON in instance settings (Performance tab) → within ~5 s the Discord profile shows the "playing Minecraft" card; OFF → card disappears inside the 5 s acceptance window.
2. Discord **closed**: toggle on → status line must explain the failure (unreachable / pipe unavailable), launcher keeps working, no error dialogs; reopen Discord → presence auto-resyncs without touching the toggle.
3. Busy-pipe sanity (optional): open several Discord windows — the launcher must not hang (the dial runs under a 750 ms context; CI pins the contract, here confirm the UX is silent-degrade, not spinner).

## Real Modrinth .mrpack
4. Modpacks page → pick any pack with a `.mrpack` file → import: instance appears, plan/progress UI honest, launcher resolves the file **from its own API call** (devtools: the `ImportMrPackFromURL` payload carries only `project_slug` + `version_id` — no url, no hashes).
5. Launch the imported instance once (vanilla+mods resolve through the normal pipeline).
6. Mid-download network kill (pull LAN / firewall the CDN after ~50 %): status shows failed with transport error; retry works; `%TEMP%` contains **no** `nord-mrpack-url-*` leftovers (check Explorer/search).

## Loaders (the wizard's four promises)
7. Create via wizard with **Fabric** for a current release → launch. PASS = game window.
8. Same with **Quilt** (pick an MC version Quilt covers).
9. Same with **Forge** (promotions_slim recommended). If it does not start on the newest MC: do not ship a silent failure — mark Forge **experimental** for that range in the wizard and file the follow-up.
10. Same with **NeoForge** (GitHub-tags resolver, e.g. 1.21.x).

## Linux, WebKitGTK

12. Datapack tab on a real world: disable → physical move into `datapacks-disabled/`, in-game world still loads; enable back.

## Dev-build updater guard

## v0.7.2 round-4 additions (both webviews: WebKitGTK 6.0 default / webkit2gtk-4.1 gtk3 variant)
- **14. CSP header actually lands**: DevTools → Network → index.html response headers contain `Content-Security-Policy`; console shows NO CSP violations while browsing Modrinth + CurseForge tabs (mod icons from cdn.modrinth.com / mediafiles.forgecdn.net MUST render - img-src was the predicted breakage, not style-src); then run `eval("1+1")` in the console → must throw `Refused to evaluate a string as JavaScript`.
- **15. Outbound URL surface (corrected in round 6)**: the bound method is `OpenExternal` (there is no `OpenURL`), and in Wails beta.20 the console call shape is the binding object, not `window.wails.invoke`. In the same console run:
  ```js
  const A = window.go.wails.WailsAdapter;
  await A.OpenExternal('file:///etc/passwd')                 // => error: open-url: refusing scheme "file:" (only http/https may reach the OS handler)
  await A.OpenExternal('ms-msdt:xxx')                         // => refusing scheme "ms-msdt:"
  await A.OpenExternal('https://modrinth.com/mod/sodium')     // => system browser opens
  ```
  No external process spawn for the first two (`ps aux | grep -E "xdg-open|explorer"` before/after; on Windows `Get-Process | ? Name -match 'explorer|cmd'`).
- If the header is missing on webkit2gtk while the `<meta>` fallback in index.html is present, the policy still applies (meta wins as fallback); record which path enforced it in the acceptance notes.


## v0.7.2 round-5 additions
- **16. External links (BOTH webviews: WebView2 / WebKitGTK-6.0 / webkit2gtk-4.1)**: open a mod page, click any link inside a description/changelog/source URL. Required: the URL opens in the SYSTEM default browser; the launcher window's own address never changes (no navigation away, no white screen, no extra app window/popup). Also try Ctrl+click and middle-click - both must open the system browser, not an embedded window.
- **17. Update circle rehearsal artifacts**: download the `rehearsal-release-assets` artifact from the dispatch run, run `sha256sum -c SHA256SUMS.txt` and `go run ./scripts/verify_manifest_sig.go --dist <dir> --channel stable --staging-pubkey` - must pass; without `--staging-pubkey` it must FAIL (production key must not accept a rehearsal signature).
- **18. 0.7.1 -> 0.7.2 upgrade on a clean machine**: install v0.7.1 and confirm the OLD client accepts the new signature. Note there is NO feed override knob to point at a test manifest: `cmd/launcher/main.go:183` pins `https://github.com/Aethelis-Projects/Aethelis-Launcher/releases/latest/download/manifest-stable.json`, so this item can only be executed after the tag is published (that is the planned order). A local emulation must be built with `-ldflags "-X main.version=0.7.1"` (lowercase `v`; without it `IsDevVersion` short-circuits and no request is made - that is item 13, not a bug) (ldflags `VERSION` path, new gates, `metrics.json`), applies the update and reports 0.7.2 afterwards. No release announcement until this passes.

- **19. Drag & drop onto the window (round 6, owner p3)**: drag (a) a file from the file manager and (b) a link from a browser onto the launcher window. Required in BOTH webviews (WebView2 / WebKitGTK-6.0 / webkit2gtk-4.1): the app stays on the same screen - no navigation to `file://`, no white page, no second window; a dropped http(s) link opens in the system browser. The click guard cannot cover this (a drop is not a click), so dragover/drop are handled at `window` level and only when nothing in-app consumed the event.
- **20. Production key preflight (round 6, owner p2)**: in the dispatch dry-run log, the publish job must show `PASS preflight -selftest: key parser OK, staging pubkey … is isolated from the client trust root …`. If `ED25519_PRIVATE_KEY` is not configured, the same log must show a `::warning::` naming it - that warning means the release is NOT ready to tag, because the tag run hard-fails there. When the secret IS configured, expect `PASS preflight: the production secret signs exactly what the shipped client will trust.` and no staging fallback anywhere: on the tag run the manifest verification line must read `signature valid against the client public key` with no `--staging-pubkey`, and in the rehearsal the extra line `PASS: the production client key rejects the rehearsal signature`.
- **21. E2E stage 16 (client refuses rehearsal signatures)**: `go run ./cmd/e2e/main.go` ends with `ALL 16 E2E STAGES PASSED` and the line `PASS: Step 16 a staging-signed manifest is refused by the production client`. If someone ever wires the staging key into the client, this stage fails - record it in the acceptance notes.
